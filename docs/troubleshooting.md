# Типовые неисправности

## В пакетах нет `tmms`, только `tmst`

Признак: форвардер работает, пакеты приходят на LNS, но GPS-времени нет.

1. `./scripts/05-verify.sh` — раздел 2 показывает, идёт ли NMEA.
2. `gps_tty_path` в `/etc/lora-gateway/global_conf.json` не должен быть пустым:
   пустая строка полностью выключает GPS-поток форвардера.
3. `fake_gps` должен быть `false`. При `true` форвардер выдаёт «время»
   из опорных координат — для меток это бесполезно.
4. В журнале ищите сообщения GPS-потока:
   `journalctl -u lora-pkt-fwd | grep -iE 'gps|time ref'`.
5. Нет фикса: в `$GxRMC` шестое поле должно быть `A`, а не `V`. Холодный старт
   под открытым небом — 30–90 с, в помещении фикса может не быть вовсе.

## NMEA не читается с `/dev/ttyAMA0`

* Порт уже занят: пакет-форвардер или `gpsd`. Проверить: `sudo fuser -v /dev/ttyAMA0`.
  Один порт — один владелец, см. `GPS_MODE` в README.
* Осталась консоль ядра: `grep console /boot/firmware/cmdline.txt` должно быть пусто
  по части `serial0/ttyAMA0/ttyS0`; `systemctl status serial-getty@ttyAMA0`.
* Не применился `dtoverlay=disable-bt` — нужна перезагрузка после шага 1.
* Не та скорость: модуль отдаёт 9600 бод. Проверка вручную:
  `stty -F /dev/ttyAMA0 9600 raw -echo && timeout 5 cat /dev/ttyAMA0`.
* Символы «мусорные» — почти всегда mini-UART без `core_freq_min`.

## `/dev/pps0` есть, импульсов нет

Сначала убедитесь, что это вообще нужно: на метки пакетов PPS со стороны
Raspberry Pi не влияет (см. `docs/architecture.md`). Если нужен точный
системный час:

* нет фикса GNSS — PPS у большинства модулей появляется только после фикса;
* PPS платы не заведён на GPIO, указанный в `PPS_GPIO`. Распиновка зависит от ревизии
  платы; переберите кандидатов, меняя `gpiopin=` в `dtoverlay=pps-gpio`, либо
  поставьте `ENABLE_PI_PPS=0` и оставьте дисциплину часов на NTP;
* проверка: `sudo ppstest /dev/pps0` — должны идти строки `assert`.

## chrony не выбирает PPS

`refclock PPS` без опорного источника привязывается к ближайшей секунде и
требует, чтобы системные часы уже были точнее ±0.4 с. Поэтому NTP-серверы в
основном `chrony.conf` (`pool …`) должны остаться включёнными. Смотрите
`chronyc sources -v`: у строки `GPPS` не должно быть пометки отбраковки.
В режиме `gpsd` вместо этого используются `SHM 0` (NMEA) и `SHM 1` (PPS).

## Форвардер не стартует: концентратор не отвечает

```
ERROR: [main] failed to start the concentrator
```

* `dtparam=spi=on` и перезагрузка; `ls -l /dev/spidev0.0`.
* Неверные пины сброса. В `gateway.env` — `SX1302_RESET_PIN` и др., по умолчанию
  значения референс-дизайна CoreCell (23/18/32/13). Проверка:
  `sudo /opt/sx1302_hal/tools/reset_lgw.sh start && sudo /opt/sx1302_hal/util_chip_id/chip_id -d /dev/spidev0.0`
  — должен вывести EUI. После смены пинов повторите шаг 2 (скрипт правит
  `reset_lgw.sh`).
* Питание: плата чувствительна к просадкам, нужен источник на 3 A.
* Порт занят другим экземпляром: `sudo systemctl stop lora-pkt-fwd` перед
  ручными запусками тестовых утилит.

## Ошибка при включении `fine_timestamp`

Если `lgw_start` ругается на конфигурацию тонких меток — на плате стоит SX1302,
а не SX1303, либо версия HAL старше, чем поддержка `fine_timestamp`. Проверьте
маркировку чипа и версию `HAL_VERSION`; временное решение — `FTIME_MODE=off`,
GPS-время (`tmms`) при этом сохраняется.

## `ftime` появляется не у всех пакетов

Это нормально: тонкая метка считается только для LoRa с BW 125 кГц и в пределах
SF, разрешённых режимом (`all_sf` — SF5…SF12, `high_capacity` — SF5…SF10).
При слабом сигнале блок тонких меток может не выдать результат, и поле просто
отсутствует в конкретном кадре.

## Время в `tmms` расходится с UTC на ~18 секунд

Так и должно быть: `tmms` — время шкалы GPS, которая не учитывает
високосные секунды. На 2026 год разница GPS − UTC составляет 18 с. Поле `time`
в том же кадре содержит уже UTC. `tools/gwsniff.py` печатает расшифровку
`tmms` как «GPS», без вычитания поправки.

## Полезные команды

```bash
journalctl -u lora-pkt-fwd -f                      # журнал форвардера
chronyc tracking && chronyc sources -v             # состояние часов
sudo fuser -v /dev/ttyAMA0                         # кто держит UART
sudo ppstest /dev/pps0                             # импульсы PPS
cd /opt/sx1302_hal/libloragw && sudo ./test_loragw_gps   # NMEA+PPS+счётчик
python3 tools/gwsniff.py -p 1700                   # что реально уходит на LNS
```
